# Список изменений

Все заметные изменения проекта Music Tools документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [2.0.0] - 2026-11-28

### Добавлено

- Подпись манифеста обновления (Ed25519): неподписанный или повреждённый
  манифест не принимается, хеш и адрес загрузки проверяются только после
  проверки подписи.
- Каналы обновления stable и beta с выбором в настройках.
- `scripts/gen_keys.py` для однократной генерации пары ключей подписи.
- `scripts/make_manifest.py --key` подписывает манифест, `--verify` проверяет его.
- `core/settings.py`: настройки в `%APPDATA%\MusicTools\settings.json`,
  устойчивые к отсутствию и повреждению файла.
- Каркас приложения на Tauri 2 и Rust: реестр инструментов, модель задач
  с отменой и событиями прогресса, настройки, журналирование, трей.
- `docs/TAURI_ARCHITECTURE.md` с описанием контракта IPC, модели задач
  и порядка переноса функциональности.
- Инструмент «Скачивание» на Rust: поиск сайдкаров (yt-dlp, ffmpeg) по
  каталогам ресурсов, приложения и `PATH`, предпросмотр ссылки, форматы
  mp4/mp3/wav с матрицей качества, прогресс по выводу yt-dlp и ffmpeg,
  отмена с завершением дерева процессов и сохранение результата через
  диалог с защитой от перезаписи (`name (1).ext`).
- Инструмент «Конвертация» на Rust: очередь файлов, форматы mp3/wav/flac/ogg
  с матрицей качества из PyQt-версии, общий прогресс по очереди, отмена,
  продолжение работы после ошибки одного файла и сохранение в выбранную папку.
- Обновление приложения на Rust: проверка манифеста `latest.json` с
  подписью Ed25519 и SHA-256, каналы stable/beta, сравнение версий,
  загрузка с прогрессом и отложенная установка через скрипт с откатом.
  Проверка при старте выполняется в фоне и не блокирует интерфейс.
- Проверка совместимости подписи: канонизация манифеста в Rust побайтово
  совпадает с Python-версией, а манифест, подписанный
  `scripts/make_manifest.py`, проходит проверку в Rust.
- Сайдкары упаковываются в установщик: `scripts/prepare_sidecars.py`
  готовит `yt-dlp.exe` и `ffmpeg.exe` в `src-tauri/resources`, а сборка
  отказывается собирать установщик без них.
- Самообновление `yt-dlp`: обновляемая копия в `%LOCALAPPDATA%\MusicTools\bin`
  имеет приоритет над закреплённой, команды `ytdlp_status` и `ytdlp_update`,
  проверка SHA-256, атомарная подмена с откатом и управление на вкладке
  «О программе».
- Вкладка «О программе»: найденные программы с путями и источником,
  рабочие ссылки на репозиторий, выпуски и сообщения о проблемах.

### Исправлено

- `.gitignore` больше не скрывает `src/lib`: правило `lib/` было задумано для
  корневого каталога Python-сборки и исключало из репозитория `ipc.ts` и
  `panes.ts`, из-за чего клон проекта не собирался.
- В релизной сборке каталог ресурсов определялся как каталог exe, а не
  `<каталог установки>\resources`: упакованные `yt-dlp.exe` и `ffmpeg.exe`
  не находились, и инструменты падали с ошибкой поиска. Ищутся оба варианта.
- Журнал пишется в `%APPDATA%\MusicTools`, а не рядом с exe: каталог
  установки может быть защищён от записи обычным пользователем.
- `src-tauri/Cargo.toml` был повреждён перекодировкой (комментарии в cp1251
  с потерянными байтами); файл перезаписан в UTF-8.
- Скачивание падало на роликах с русскими названиями (`yt-dlp завершился
  с кодом 120`, `[Errno 22] Invalid argument`): замороженный `yt-dlp.exe`
  печатает название в cp1251, а чтение вывода требовало UTF-8, из-за чего
  pipe закрывался и yt-dlp не мог писать. Теперь вывод читается побайтово,
  а строки декодируются как UTF-8 с откатом на Windows-1251.

## [1.1.0] - 2026-11-24

### Добавлено

- Манифесты зависимостей: `requirements.txt` (runtime) и `requirements-dev.txt`
  (pytest, PyInstaller, необязательные линтеры), закреплённые на проверенных версиях.
- `pyproject.toml` с метаданными проекта и конфигурацией pytest, ruff и black.
- `CHANGELOG.md` для ведения истории версий.
- `docs/BUILD.md` с инструкцией по сборке приложения и установщика.
- `.editorconfig` для единообразного форматирования файлов.
- Тест `tests/test_version_sync.py`, проверяющий согласованность версии между
  `utils/constants.py`, `pyproject.toml` и `installer.iss`.
- Каркас инструментов `core/tools`: единый контракт задач `ToolWorker`, описание
  инструмента `ToolDescriptor` и реестр `ToolRegistry`. Вкладки интерфейса
  собираются из реестра, поэтому новые инструменты добавляются одним модулем.
- `scripts/make_manifest.py` для генерации манифеста обновления с контрольной суммой.
- `docs/RELEASE.md` с порядком выпуска версии.
- Тесты: реестр инструментов, сборка главного окна, перетаскивание файлов,
  проверка манифеста и целостности обновления.

### Изменено

- `main.spec` переоформлен для сопровождения, UPX отключён ради корректной
  подписи кода и репутации в антивирусах.
- Из `.gitignore` удалено правило `*.spec`, чтобы спек сборки попадал в репозиторий;
  добавлены правила для логов и временных файлов загрузок.
- Установщик больше не требует прав администратора: `PrivilegesRequired=lowest`,
  каталог установки `{autopf}` (Program Files при повышении прав, иначе
  `%LOCALAPPDATA%\Programs`), запуск приложения через `runasoriginaluser`.
  Добавлен постоянный `AppId`, чтобы обновление заменяло предыдущую установку.
- Имя записи автозапуска берётся из единой константы `APP_NAME` и совпадает
  с установщиком; отображаемое имя приложения приведено к `Music Tools`.
- Автообновление переведено на манифест `latest.json`: адрес загрузки, размер
  и контрольная сумма берутся только из него.
- Перетаскивание файлов использует явный режим `DropOnly`, папки обходятся
  рекурсивно, дубликаты отсекаются по нормализованному пути.
- Проверка обновлений выполняется в фоновом потоке после запуска окна; запуск
  больше не ждёт ответа сети. Загрузка обновления также идёт в отдельном потоке
  с отображением прогресса в трее.
- Копирование готовых файлов вынесено из интерфейсного потока в отдельный
  с прогрессом и возможностью отмены. Существующие файлы больше не перезаписываются:
  к имени добавляется номер.
- Извлечение аудио через ffmpeg сообщает прогресс внутри файла, а не только
  по завершении каждого файла.
- Потоки завершаются кооперативно: отмена с ожиданием вместо принудительного
  `QThread.terminate()`.
- Метка качества в интерфейсе зависит от формата: `Resolution` для видео,
  `Bitrate` для mp3 и ogg, `Bit depth` для wav и flac.

### Исправлено

- Перетаскивание файлов не работало в установленной версии: приложение
  запускалось с правами администратора, и Windows блокировала передачу файлов
  из Проводника на уровне UIPI.
- Версии сравнивались как строки, из-за чего часть обновлений не предлагалась.
- Запуск из исходников мог заменить `python.exe` скачанным файлом обновления.
- При отсутствии exe-файла в релизе скачивалась HTML-страница вместо программы.
- Отмена загрузки не срабатывала во время извлечения аудио через ffmpeg.
- Временные каталоги не удалялись при ошибке задачи.
- Ярлык на рабочем столе не создавался при установке без прав администратора.
- Окно зависало при копировании больших файлов.
- При ошибке конвертации пользователю не сообщалась причина: вывод ffmpeg
  полностью отбрасывался.
- Адрес ffmpeg для yt-dlp мог передаваться пустой строкой, если программа
  запускалась без встроенного ffmpeg.
- Опечатка в сообщении об отмене конвертации.
