# Порядок выпуска релиза

Автообновление берёт данные только из ассета `latest.json` в последнем релизе
GitHub. Релиз без `latest.json` не является автообновляемым: приложение
сообщит об отсутствии обновления. Хэш `sha256` в манифесте обязан совпадать с
установщиком, иначе установка будет отклонена.

## Чек-лист

1. Поднять версию одновременно в:
   - `utils/constants.py` — `VERSION`
   - `pyproject.toml`
   - `installer.iss`
   - `CHANGELOG.md`
2. Сгенерировать ключи подписи (только один раз, при первой подписанной
   публикации). Приватный ключ обязан жить ТОЛЬКО в секретах CI и никогда
   не попадать в репозиторий; в `.gitignore` добавьте `keys/private.key`.

   ```
   python scripts/gen_keys.py --out-dir keys
   ```

   Скрипт печатает строку `PUBLIC_KEY = "..."` — вставьте её в
   `core/updater.py`, заменив плейсхолдер.
3. Собрать приложение и установщик.
4. Сгенерировать и подписать манифест:

   ```
   python scripts/make_manifest.py --version 1.1.0 ^
       --file dist\MusicTools_v1_1_0_setup.exe ^
       --url https://github.com/SchazyDev/MusicTools/releases/download/v1.1.0/MusicTools_v1_1_0_setup.exe ^
       --notes "Краткое описание изменений" ^
       --channel stable ^
       --key keys\private.key ^
       --out latest.json
   ```

   Канал выбирается флагом `--channel` (`stable` или `beta`).
5. Проверить подпись перед публикацией:

   ```
   python scripts/make_manifest.py --verify latest.json --public-key keys\public.key
   ```

   Шаг обязателен: он подтверждает, что канонизация и ключ согласованы.
6. Создать GitHub Release с тегом `vX.Y.Z` (тег обязателен, из тега читается версия).
7. Приложить к релизу установщик и `latest.json`.
8. Проверить обновление: запустить предыдущую версию и убедиться, что
   приложение предлагает новую версию, скачивает файл, проверяет подпись
   и хэш, и перезапускается.

## Замечания

- Имя ассета манифеста строго `latest.json`.
- Платформенный ключ в манифесте — `windows-x86_64`.
- Неподписанный или непроверяемый манифест НЕ будет предложен пользователям
  канала `stable`: проверка подписи работает fail-closed. Такой релиз
  автообновляемым не является, его нужно считать только отладочным.
- Пользователь канала `stable` никогда не получает `beta`, и наоборот:
  канал манифеста обязан совпадать с запрошенным.
- Canonical payload для подписи — тело манифеста без ключа `signature`,
  сериализованное как
  `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`
  в UTF-8. Скрипт подписи и приложение используют ровно эту канонизацию.
- Если `sha256` не совпадает, скачанный файл удаляется, установка не выполняется.
