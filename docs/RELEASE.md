# Порядок выпуска релиза

Автообновление берёт данные только из ассета `latest.json` последнего релиза
GitHub (`releases/latest`). Приложение скачивает файл из манифеста, проверяет
подпись Ed25519 и SHA-256, затем заменяет свой исполняемый файл через
bat-скрипт с `.old`-бэкапом и откатом при ошибке.

## Что публикуется

| Файл | Назначение |
| --- | --- |
| `MusicTools-X.Y.Z.exe` | portable-копия `music-tools.exe`; именно её указывает `latest.json` |
| `Music Tools_X.Y.Z_x64-setup.exe` | установщик NSIS для ручной установки без прав администратора |
| `Music Tools_X.Y.Z_x64_en-US.msi` | MSI для установки администратором или через домен |
| `latest.json` | подписанный манифест обновления |

Манифест обязан указывать на portable exe, а не на установщик: и Tauri-, и
PyQt-версия заменяют свой исполняемый файл скачанным, а не запускают
установщик. Установщики прикладываются к релизу для ручной установки.

GitHub заменяет пробелы в именах ассетов на точки: локальный
`Music Tools_X.Y.Z_x64-setup.exe` на странице релиза называется
`Music.Tools_X.Y.Z_x64-setup.exe`. На установку и обновление это не влияет,
но ссылки в описании релиза нужно давать по фактическим именам.

## Чек-лист

1. Поднять версию одновременно в:
   - `package.json`;
   - `src-tauri/Cargo.toml`;
   - `src-tauri/tauri.conf.json`;
   - `CHANGELOG.md` (раздел версии и ссылки внизу).
2. Собрать установщики: `npm run tauri build`. Сборка сама проверяет наличие
   сайдкаров (`npm run sidecars:check`), типы фронтенда и собирает `dist`.
3. Подготовить каталог релиза:

   ```
   mkdir release
   copy "src-tauri\target\release\music-tools.exe" "release\MusicTools-X.Y.Z.exe"
   copy "src-tauri\target\release\bundle\nsis\Music Tools_X.Y.Z_x64-setup.exe" release\
   copy "src-tauri\target\release\bundle\msi\Music Tools_X.Y.Z_x64_en-US.msi" release\
   ```

4. Сгенерировать и подписать манифест (ключ `keys\private.key` в репозиторий
   не попадает):

   ```
   python scripts/make_manifest.py --version X.Y.Z ^
       --file release\MusicTools-X.Y.Z.exe ^
       --url https://github.com/SchazyDev/MusicTools/releases/download/vX.Y.Z/MusicTools-X.Y.Z.exe ^
       --notes "Краткое описание изменений" ^
       --channel stable ^
       --key keys\private.key ^
       --out release\latest.json
   ```

5. Проверить подпись перед публикацией:

   ```
   python scripts/make_manifest.py --verify release\latest.json --public-key keys\public.key
   ```

   Шаг обязателен: он подтверждает, что канонизация и ключ согласованы.

6. Создать GitHub Release с тегом `vX.Y.Z` (тег обязателен, из него читается
   версия).
7. Приложить к релизу все четыре файла из `release\`.
8. Проверить обновление: запустить предыдущую версию, убедиться, что она
   предлагает новую, скачивает файл, проверяет подпись и хэш и
   перезапускается уже новой версией. В журнале должны появиться строки
   «манифест обновления: подпись проверена» и «обновление скачано и проверено».

## Переход с PyQt-версии 1.1.0

- Обновлятор 1.1.0 заменяет свой exe скачанным файлом, поэтому манифест
  указывает на portable exe: после обновления в каталоге 1.1.0 окажется
  Tauri-приложение.
- `ffmpeg.exe` в каталоге 1.1.0 уже есть, Tauri найдёт его рядом с exe.
- `yt-dlp.exe` в 1.1.0 не поставлялся (использовался Python-модуль), поэтому
  после перехода его нужно скачать на вкладке «О программе» либо установить
  2.0.0 установщиком.
- Рекомендуемый путь для пользователей 1.1.0 — ручная установка 2.0.0:
  автообновление оставляет рядом с exe файлы старой версии.

## Замечания

- Имя ассета манифеста строго `latest.json`.
- Платформенный ключ в манифесте — `windows-x86_64`.
- Неподписанный или непроверяемый манифест не предлагается пользователям
  канала `stable`: проверка подписи работает fail-closed.
- Пользователь канала `stable` никогда не получает `beta`, и наоборот: канал
  манифеста обязан совпадать с запрошенным.
- Canonical payload для подписи — тело манифеста без ключа `signature`,
  сериализованное как
  `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`
  в UTF-8. Скрипт подписи и приложение используют ровно эту канонизацию.
- Если `sha256` не совпадает, скачанный файл удаляется, установка не
  выполняется.
- Приватный ключ `keys/private.key` хранится только вне репозитория. Потеря
  ключа означает, что установленные версии больше не смогут получать
  обновления: придётся выпускать новую версию с другим открытым ключом и
  просить пользователей установить её вручную.
